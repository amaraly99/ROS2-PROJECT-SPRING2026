Functions

project() → (u, v, bw, bh) | None
  1. no drone or no target pose yet: None
  2. drone pose older than pose_stale_sec: None
  3. delta = target − drone (world)
  4. fwd = dx·cos(yaw) + dy·sin(yaw); left = −dx·sin(yaw) + dy·cos(yaw); up = dz
  5. th = pitch_sign × pitch; fwd_p = fwd·cos(th) + up·sin(th); up_p = −fwd·sin(th) + up·cos(th)
  6. Zc = fwd_p; Xc = −left; Yc = −up_p
  7. Zc ≤ 0.1: None. Max range set and Zc above it: None.
  8. u = fx·Xc/Zc + cx0; v = fy·Yc/Zc + cy0
  9. outside image plus margin: None
  10. bh = fy·known_h/Zc; bw = bh×aspect
steps 2 to 9 move into pose_geometry and PosePerception (copied, not removed)
tick() → publish
  1. proj = project()
  2. proj exists and a random draw ≥ dropout_prob: add noise, fill one Detection
  3. publish the array (empty if no target)
  4. log once per second, with the reason when not visible

Contract

who reads what
  1. A box controller reads box fields and ignores pose_valid.
  2. A pose controller returns zero velocity when pose_valid is false.
  3. In pose mode the box fields hold the values the box would have (ex, ey, ratio, Z = Zc). So the ratio law reproduces Path A.
